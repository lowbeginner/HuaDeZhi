# 花得值 · Android 个人消费账本

原生 Kotlin / Jetpack Compose 应用，支持 Android 8.0（API 26）及以上。数据保存在本机 Room 数据库，无需账号、服务器或网络权限。

记录日常付款，也记录健身卡、游泳卡、会员等长期消费的每一次使用。实际单次成本始终等于购买金额除以使用记录数量；使用服务不会重复增加支出。

## 安装和打开项目

交付 APK 位于 `dist/`。将 `HuaDeZhi-1.0.0.apk` 传到手机，用系统文件管理器打开并安装。第一次安装可能需要允许该文件管理器“安装未知应用”。

Android Studio 选择 **Open**，打开本目录 `ExpenseTracker`，等待 Gradle 同步后运行 `app`。首次构建需要联网下载依赖。

- JDK 17 或 21；Android SDK Platform 35、Build Tools 35.0.0。
- AGP 8.9.2、Gradle 8.11.1、Kotlin 2.1.20、Compose BOM 2025.04.01、Room 2.7.1。
- `local.properties` 是本机 SDK 路径，不应提交。换电脑后让 Android Studio 重新生成，或设置 `sdk.dir`。
- 本机临时构建工具放在 `.tooling/`，不属于源码。独立使用 Android Studio 不依赖这个目录。

```powershell
.\gradlew.bat assembleDebug
.\gradlew.bat testDebugUnitTest lintDebug
```

如需沿用 Windows 当前 HTTP 代理，可使用 `scripts/Build.ps1`。仓库配置包含 Google 托管的 Maven Central 公共镜像，所有依赖版本固定。

## 使用

- **首页**：本月、今日、本周支出，最近付款，正在使用的长期项目。
- **记一笔**：选择单次或多次消费，输入名称、金额、分类、日期与备注。多次消费可设置开始/结束日期、固定次数及参考单次价格。
- **长期项目详情**：查看实际成本、理论成本、剩余次数、有效期和回本进度；点击“使用一次”记录当前时间，或补录历史使用。
- **使用历史**：可修改日期、时间、备注，或删除误记的一次使用。数量和成本随之重新计算。
- **记录**：搜索名称，按消费类型、分类筛选，按日期或金额升降序排列。
- **统计**：按购买日期统计今日、本周（周一开始）、本月、今年和全部付款，显示分类分布。
- **设置**：完整备份、完整恢复、CSV 导出，以及浅色/深色/跟随系统主题。

固定次数卡用完后不能再记录使用；可先提高总次数。新补录的使用必须在有效期内，且不能晚于当前时间；已到期项目仍可补录有效期内的历史使用。

## 换手机：完整备份与恢复

1. 旧手机进入 **设置 → 导出完整备份**，在系统文件选择器中选择保存位置。
2. 将 `.expensebackup` 文件通过微信、QQ、网盘、电脑或数据线传到新手机。若聊天软件限制文件扩展名，可作为文件压缩后传送，接收后解压。
3. 新手机安装 App，进入 **设置 → 恢复完整备份**，选择文件。
4. App 验证格式、版本、校验和、记录数量及关联关系，显示备份中的消费与使用记录数量。
5. 阅读覆盖提示并确认；所有表和设置在一个数据库事务内恢复。发生写入错误时回滚，不保留恢复到一半的数据。

**覆盖恢复会替换新手机当前账本。** 建议先导出当前数据。第一版没有合并恢复。

完整备份保存消费、多次项目、全部使用历史、分类、备注、日期、参考价格及用户设置。CSV 用于 Excel 阅读分析，不能恢复 App。CSV 包含 UTF-8 BOM、引号/换行转义及文本公式防护。

备份未加密，请自行妥善保存。校验和用于检测损坏，不用于证明文件来源。应用不会自动将数据上传云端；定期导出，卸载或清除数据前务必先备份。普通关闭、进程结束或手机重启不会主动清空数据库。

## 数据与扩展约定

目录职责：`data/` Room 实体、DAO、事务仓库；`domain/` 金额计算和校验；`backup/` ZIP/JSON 格式及 CSV；`ui/` Compose 页面；`LedgerViewModel` 协程与操作状态；`MainActivity` 系统文件选择器。

- 金额使用 `Long` 保存分，不用浮点数保存或累计；平均成本用十进制定点计算并四舍五入到分。单笔上限 999999999.99 元。
- 消费、分类和使用记录使用稳定字符串 ID；次数只由 `UsageRecord` 数量得出。
- 购买/有效日期保存 `LocalDate.toEpochDay()`，与时区无关；使用时刻保存 epoch 毫秒，按设备时区显示。
- 删除消费通过外键级联删除多次详情及使用记录；编辑使用 `Upsert`，避免 `REPLACE` 导致意外级联删除。
- 数据库 schema 当前版本 1，导出到 `app/schemas/`。升级必须添加明确的 Room `Migration`，不得使用破坏性重建。无法迁移时保留原数据库并显示错误。
- 备份格式独立版本 1，后续格式需保留 v1 解码/升级分支。当前仅接受明确支持的版本，遇到其他版本提示不兼容。
- 备份当前限制数据库 JSON 32 MiB、压缩容器约 33 MiB，避免异常文件耗尽内存。达到上限会明确失败，不会生成自称成功的不完整备份。
- 主题和 CNY 货币设置存数据库；未知设置键在备份中保留。自定义分类、多币种、预算、云同步、加密等为后续扩展，本版未实现。

详见 [备份格式](docs/BACKUP_FORMAT.md) 和 [验证记录](docs/VERIFICATION.md)。

## 长期安装与后续更新签名

正式安装使用 `dist/HuaDeZhi-1.0.0.apk`。正式包使用本项目独立生成的签名密钥。**更新时应始终使用同一个包名和同一把密钥，并提高 `versionCode`。** 这样可以覆盖升级并保留本机账本。

首次生成密钥（已有时脚本会拒绝覆盖）：

```powershell
.\scripts\New-ReleaseKey.ps1
.\gradlew.bat assembleRelease
```

请私下备份 `.signing/personal-release.jks` **和** `keystore.properties`，两者都已被 Git 忽略，也不包含在公开源码压缩包中。迁移开发电脑需要恢复这两个文件才能继续签名升级。签名密钥与消费备份用途不同，消费备份不会包含签名密钥。

不要用 debug APK 覆盖正式包，两者签名不同。如需更换签名安装，先导出完整备份，再卸载、安装并恢复。
